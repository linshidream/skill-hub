# 组件库选型

> 策展层第 2 层。平台=硬过滤，风格=软偏好。先按端筛可用库，再按第 1 层定调选风格。

## 组件库活跃度（2026-07 查证）

| 库 | 平台 | 活跃度 | 备注 |
| --- | --- | --- | --- |
| Ant Design | React/Web | 活跃（v6） | 工作型软件首选，密度高 |
| shadcn/ui | React/Web | 活跃 | 拷贝式、可重度定制，偏极简 |
| Element Plus | Vue3/Web | 活跃 | Vue 后台主流，密度高 |
| Vant | 移动 H5 | 稳定放缓 | 仍可用，新特性慢 |
| NutUI | 移动 H5/小程序 | 存疑 | 谨慎，验证后再用 |
| TDesign | 小程序/Web | 活跃 | 微信小程序首选 |
| WeUI | 微信小程序 | 低频 | 仅基础控件，复杂场景不足 |

> 查证带日期。库的活跃度会变，落地前应复核官方仓库近期提交与发版。

## 硬过滤规则（按端）

| 端 | 硬过滤 | 风格软偏好 |
| --- | --- | --- |
| Web 后台/CRM | Antd（React）/ Element Plus（Vue）/ shadcn（极简定制） | 按定调：商务→Antd/EP；极简→shadcn |
| 移动 H5 | Vant（稳定优先）/ NutUI（验证后） | 活泼移动档优先 |
| 微信小程序 | TDesign（首选）/ WeUI（仅基础） | 活泼移动档优先 |
| Java 后端 | 无 UI 库 | 原型只验流程/接口，不承诺 UI 还原 |

## 与 tokens 的关系

选定组件库后，tokens（第 3 层）在组件库的 theme 变量上覆盖：组件库定基础控件，tokens 定色板/字阶/圆角等品牌层。组件库不支持覆盖的变量，记入风险，不强行 hack。

## 禁跳层

不得在未定调（第 1 层）前直接选库。“用 Antd”不是定调；“商务高密度，因此选 Antd”才是。
