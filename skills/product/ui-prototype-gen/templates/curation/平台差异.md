# 平台差异

> 策展层第 2 层的硬过滤依据。不同端的组件库、tokens、交互约束不同，禁把桌面布局硬缩小到移动端。

## 端差异

| 维度 | Web 后台 | 移动 H5 | 微信小程序 |
| --- | --- | --- | --- |
| 组件库 | Antd / Element Plus / shadcn | Vant / NutUI(验证后) | TDesign / WeUI |
| 布局 | 多列、高密度、可滚动表格 | 单列、卡片流 | 单列、`pages/` 结构 |
| 点击区 | 鼠标精度，≥ 24px 可接受 | ≥ 44×44pt 强制 | ≥ 44×44pt 强制 |
| 圆角 | 小（商务 4）/ 统一（极简 8） | 大（圆润 12+） | 中大，服从小程序规范 |
| 字体 | 系统无衬线 | 系统无衬线 | 系统无衬线（小程序字体受限） |
| 阴影 | 克制 | 可柔和 | 服从原生规范，慎用重阴影 |

## 硬过滤规则

- **平台先于风格**：先按端筛可用组件库（小程序不能用 Antd），再按风格选 preset。
- **不硬缩小**：桌面高密度后台不得直接缩到移动屏；移动场景用活泼移动 preset 重排。
- **小程序还原 gap**：HTML 原型 → WXML/WXSS 转换成本大，原型只验交互和内容范围，不承诺还原。写进 spec 风险。

## 后端无 UI

Java 后端项目无界面，原型只用于验证业务流程和接口边界，不承诺 UI 还原。组件库/tokens 不适用，自检清单第 1–4 项可标注“不适用（后端）”，但第 5–8 项仍要过（流程/状态/路径）。
