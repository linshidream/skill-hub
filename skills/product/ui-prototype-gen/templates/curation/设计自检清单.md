# 设计自检清单

> 策展层第 4 层，也是 `product-lifecycle` N3 自检 gate 的检查依据。8 项 gate，pass 才生成原型 / 才进客户评审。质量不靠客户兜底。

## 8 项 Gate

每项 pass 记 `self_check.status=pass`；任一 fail 记 `self_check.status=fail` 并把失败项写入 `self_check.issues`，回 N2 重改。

### 1. 风格定调落地

- [ ] 原型 `tokens-override.css` 头注释有风格定调句（或 DESIGN.md Overview 节）。
- [ ] 选用的 tokens preset 与定调句一致，未漂移。

### 2. 组件库与端一致

- [ ] 组件库按平台硬过滤选取（Web 后台≠小程序库）。
- [ ] 组件库活跃度已查证（非存疑库）。

### 3. tokens 符合量化阈值

- [ ] 对比度 ≥ 4.5:1（text_primary 对 bg、text_secondary 对 surface）。
- [ ] 8pt 栅格（间距为 8 的倍数，4 用于微调）。
- [ ] 字阶层级 ≤ 5。
- [ ] 字体家族 ≤ 1 套。
- [ ] 点击区 ≥ 44×44pt（移动/活泼档强制）。

### 4. 色板纪律

- [ ] 低饱和中性主导，主色稀用（极简 ≤ 10%）。
- [ ] 不用单一色相铺满全局。
- [ ] 圆角全局统一，不混用。

### 5. 页面覆盖

- [ ] 主流程页面齐全（index/home/detail/form 等）。
- [ ] 关键状态可见（空态、异常态、加载态）。
- [ ] 必须展示的字段、状态、操作都在。

### 6. 可点击与可读

- [ ] 导航、按钮、流程跳转真实可点击。
- [ ] 文本在容器内可读，不互相遮挡。
- [ ] 无元说明（“这是原型”等）。

### 7. 无敏感数据

- [ ] 不含真实手机号、证件号、密钥、token、生产配置。
- [ ] 用占位或脱敏数据。

### 8. 路径回写

- [ ] `prototype_path` 已回写 `.product-flow-state.json`。
- [ ] `prototype_pages` 关键页面清单已记录。

## 判定

- 全 pass：`self_check.status=pass`，清空 issues，进 N4 客户评审。
- 有 fail：`self_check.status=fail`，列 issues，回 N2 按问题项重改，不把质量推给客户。
